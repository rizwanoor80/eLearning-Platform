## §3 What changed
Merged to `main` as `94d8afa` (PR #53), docs only after it. 16b as merged:
- **16b as built (`3862a81`, PR #53).** `scripts/vite-fonts.js` (new) holds the one list of the three font families (Schibsted Grotesk 400/500/700, Quicksand 600, IBM Plex Mono 400/500) and reads `VITE_FONTS_INLINE` from the shell environment. Unset, empty or anything but the exact string `0`: the same three `bunny()` definitions as before go to the plugin unchanged, so a build is as before (the self-hosted path). `0`: the plugin gets no families, so it fetches nothing, and a build-only, client-only plugin writes `fonts-manifest.json` whose style is an `@import` of Bunny's css2 URL for the same families; the framework's own `@fonts` renders it, no font file lands in `public/build`. `vite.config.ts` uses the helper. It is a switch and not an automatic fallback on purpose (§6, advisor): without the flag a blocked build still fails loudly, so no deploy silently moves from self-hosted to by-URL fonts. `tests/Unit/ViteFontsFallbackTest.php` (14 tests).
- **The High finding (REVIEW 2, CYCLE-LOG).** The by-URL manifest of `3862a81` has `families: {}`. The Filament admin calls `Vite::fonts('schibsted-grotesk')` with an alias in its head on **every admin page** (`app/Providers/Filament/AdminPanelProvider.php:60`), and the framework refuses an alias that is not in `families` (`ViteFonts.php:95-125`: it also ignores `style.inline` when an alias is given and reads `style.familyStyles[alias]`).
