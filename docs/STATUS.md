## §3 What changed
Nothing new on `main` except docs. On the branches:
- **16b as built (`3862a81`, PR #53).** `scripts/vite-fonts.js` (new) holds the one list of the three font families (Schibsted Grotesk 400/500/700, Quicksand 600, IBM Plex Mono 400/500) and reads `VITE_FONTS_INLINE` from the shell environment. Unset, empty or anything but the exact string `0`: the same three `bunny()` definitions as before go to the plugin unchanged, so a build is as before (the self-hosted path). `0`: the plugin gets no families, so it fetches nothing, and a build-only, client-only plugin writes `fonts-manifest.json` whose style is an `@import` of Bunny's css2 URL for the same families; the framework's own `@fonts` renders it, no font file lands in `public/build`. `vite.config.ts` uses the helper. It is a switch and not an automatic fallback on purpose (§6, advisor): without the flag a blocked build still fails loudly, so no deploy silently moves from self-hosted to by-URL fonts. `tests/Unit/ViteFontsFallbackTest.php` (14 tests).
- **The High finding (REVIEW 2, CYCLE-LOG).** The by-URL manifest of `3862a81` has `families: {}`. The Filament admin calls `Vite::fonts('schibsted-grotesk')` with an alias in its head on **every admin page** (`app/Providers/Filament/AdminPanelProvider.php:60`), and the framework refuses an alias that is not in `families` (`ViteFonts.php:95-125`: it also ignores `style.inline` when an alias is given and reads `style.familyStyles[alias]`). So after `VITE_FONTS_INLINE=0 npm run build`, every `/admin` page is a 500, and the Filament tests fail. The layout's call (no alias) works, which is all I had tested. Reproduced by the reviewer and by me (four Filament test failures against a flag-0 build of the old helper).
- **The held fix (`98fcb44`).** The by-URL manifest now has one `families` entry per alias, `style.familyStyles[alias]` (that family's own `@import`), `style.variables[alias]` (`--font-<alias>: "<Family>";`) and a combined `style.inline`, all built from the same `FONT_FAMILIES` list. The test file grows to 20 tests / 87 assertions and now calls the real `Illuminate\Foundation\ViteFonts` for the no-alias call and for each of the three aliases. Proof: the 20 tests against the helper of `3862a81` — 5 fail; a mutant that gives every alias the combined `@import` of all three families instead of its own — 3 fail; the fixed helper — 20 pass; a build with `fonts.bunny.net` blocked and the flag set succeeds (72 files, no `.woff*`) and renders both the layout call and the admin call; the whole suite passes against that flag-0 build (2646 / 13419), where the old helper's flag-0 build fails the Filament tests; the normal build is byte-identical to the baseline (CYCLE-LOG VERIFICATION 02:05).
