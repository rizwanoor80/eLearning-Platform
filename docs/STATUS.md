## §6 Mismatches
- **15c: advice adapted, not implemented.** Consultation 1 said to refuse every code point that has a Unicode numeric value. ICU's `IntlChar::getNumericValue(0xA8E3)` is `NO_NUMERIC_VALUE`, so that rule would not catch the combining Devanagari digits U+A8E0 to U+A8E9 (the cycle-14 masker gap (a)), and Han numerals such as 一 and 二 are letters with a numeric value, so it would refuse real names. Instead `\x{A8E0}-\x{A8FF}` is carved out of the allowed marks and a sweep test walks the digit categories and marks; review round 1 added a cap of seven numerals (`NUMERAL_LIMIT`, counting numeric-value code points plus a Hangul list) so a long digit run is refused while 王一二 and 이일오 are admitted.
