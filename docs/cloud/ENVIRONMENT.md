## 1. Environment settings (one-time, in the claude.ai dialog)

**Name:** `trustutor`
**Network access:** Custom, with "Also include default list of common package managers" ticked, plus these domains:
```
ppa.launchpadcontent.net
keyserver.ubuntu.com
rehearsal.trustutor.com
fonts.bunny.net
```
(2026-10-15: `api.daily.co` dropped — unused; `fonts.bunny.net` added — the Vite fonts plugin fetches it at build time.)
(`ppa.*` and `keyserver.*` are only for installing PHP 8.4; `rehearsal.trustutor.com` lets CC curl the site for smoke checks. `raw.githubusercontent.com`, where `scripts/fetch-phpstan.php` gets the PHPStan phar, comes with the default package-manager list.)

**Environment variables** (visible to anyone using the environment — no secrets except the rehearsal status token, which is read-only; the sandbox database password is not a secret):
```
APP_ENV=testing
APP_DEBUG=true
APP_URL=http://localhost
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_USERNAME=postgres
DB_PASSWORD=postgres
REDIS_CLIENT=phpredis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
ADMIN_SEED_PASSWORD=cloud-test-only
COMPOSER_ALLOW_SUPERUSER=1
BASH_DEFAULT_TIMEOUT_MS=600000
BASH_MAX_TIMEOUT_MS=1800000
TRUSTUTOR_STATUS_TOKEN=<the rehearsal read-only token; already set in the environment since the 2026-10-17 pilot>
```
**Rule (R211, 2026-10-17): no key that `phpunit.xml` sets may be in this list.** These variables are real process environment, and PHPUnit's `<env>` entries do not override a variable that already exists unless the entry has `force="true"`. The 2026-10-09 list exported `CACHE_STORE`, `SESSION_DRIVER`, `QUEUE_CONNECTION`, `MAIL_MAILER` and `DB_DATABASE`, so the R203 pilot ran the suite against the database cache, the real Redis queue and the base `elearning` database and failed 497 of 2646 tests; the same clone with those five unset passed 2646/2646 (STATUS 2026-10-17 12:27). Only connection endpoints, credentials and tool settings go here. `DB_USERNAME`/`DB_PASSWORD` exported here win over the `root`/empty values that `.env.example` puts in `.env` (Laravel does not let `.env` override an existing variable), which is why the hook's `postgres` role works although `.env` says `root`.

`APP_KEY` is generated by the setup script. Check `.env.example` for any variable added since this file was written and mirror it.

**Setup script** (runs once as root, cached ~7 days; must finish in ~5 minutes):
```bash
set -uo pipefail
export DEBIAN_FRONTEND=noninteractive
export COMPOSER_ALLOW_SUPERUSER=1
apt-get update -q
apt-get install -y -q ca-certificates curl gnupg
install -d -m 0755 /etc/apt/keyrings
curl -fsSL "https://keyserver.ubuntu.com/pks/lookup?op=get&search=0x14aa40ec0831756756d7f66c4f4ea0aae5267a6c" | gpg --dearmor -o /etc/apt/keyrings/ondrej-php.gpg
echo "deb [signed-by=/etc/apt/keyrings/ondrej-php.gpg] https://ppa.launchpadcontent.net/ondrej/php/ubuntu noble main" > /etc/apt/sources.list.d/ondrej-php.list
apt-get update -q
apt-get install -y -q php8.4-cli php8.4-pgsql php8.4-redis php8.4-mbstring php8.4-xml php8.4-curl php8.4-zip php8.4-intl php8.4-bcmath php8.4-gd php8.4-sqlite3
update-alternatives --set php /usr/bin/php8.4 || true
php -v
# The cloud GitHub proxy serves only this repository: Composer must clone packages over git, not download zipballs (R199a).
# composer.json no longer sets "preferred-install" (a project value beats the global one, ADR-028); --prefer-source is the proven path.
composer config -g preferred-install source
composer install --prefer-source --no-interaction --no-progress || echo "composer install failed; the session will retry it"
npm ci --no-audit --no-fund || echo "npm ci failed; the session will retry it"
cp -n .env.example .env || true
php artisan key:generate --force || echo "key:generate failed; the session will retry it"
exit 0
```

## 2. Per-session start (SessionStart hook — services are not cached)

Add to `.claude/settings.json` (owner-only file; planner edits it):
```json
{
  "hooks": {
    "SessionStart": [
      { "matcher": "", "hooks": [ { "type": "command", "command": "bash scripts/cloud-session-start.sh" } ] }
    ]
  }
}
```
`scripts/cloud-session-start.sh` (exits at once when not in the cloud; the committed script is the source of truth — the listing below is the 2026-10-09 shape, superseded by cycle 17's R212: password from `DB_PASSWORD`, no silent failure when `vendor/` is absent):
```bash
#!/usr/bin/env bash
[ "${CLAUDE_CODE_REMOTE:-}" = "true" ] || exit 0
service postgresql start >/dev/null 2>&1 || true
service redis-server start >/dev/null 2>&1 || true
sudo -u postgres psql -tc "SELECT 1 FROM pg_roles WHERE rolname='postgres'" >/dev/null 2>&1 || true
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'postgres';" >/dev/null 2>&1 || true
sudo -u postgres psql -tc "SELECT 1 FROM pg_database WHERE datname='elearning'" | grep -q 1 || sudo -u postgres createdb elearning
php artisan migrate --force --no-interaction >/dev/null 2>&1 || true
```

## 3. Pilot findings 2026-10-15 (R199) and what changed
- Composer zipballs from api.github.com are 403 in the cloud → the setup script sets `preferred-install source` globally and passes `--prefer-source`. The project's own `"preferred-install": "dist"` was removed from `composer.json` in cycle 16 because a project value beats the global one (Composer 2.10.1, proven locally); the default is still `dist`, so CI, local and Forge are unchanged.
- PHPStan had no git source → since cycle 16 (16a, ADR-028) `composer.json` `replace`s it and `composer install` runs `scripts/fetch-phpstan.php`, which puts the phar at `tools/phpstan.phar` from raw.githubusercontent.com and verifies it against the SHA-256 in `scripts/phpstan.sha256`. The download goes through ext-curl (installed by the setup script as `php8.4-curl`), which honours the proxy variables the cloud sets; PHP's own streams would not. **Whether `raw.githubusercontent.com/phpstan/phpstan` is reachable from the cloud is unobserved until the R203 pilot re-run**; a failed fetch leaves no phar and says so (Composer then reports the script failure, but the packages are already installed).
- Composer as root needs `COMPOSER_ALLOW_SUPERUSER=1` (now in the variables) or Pest's `--parallel` is missing.
- Wayfinder route modules are generated by `composer install` (the `post-autoload-dump` hook) since cycle 16. An environment cached before then lacks both them and the phar: run `composer install` once (it regenerates the modules and fetches the phar), not only `wayfinder:generate`.
- `npm run build` needs `fonts.bunny.net` (now in the allow-list); cycle 16 also makes the build survive without it.
- `add-apt-repository` is broken on the VM (missing `apt_pkg`); the PPA is added by hand in the script above.

## 3b. Pilot re-run 2026-10-17 (R203, cloud session 12:04–12:28) — green toolchain, one amber, cause found
- Everything cycle 16 changed works from the cloud: `composer install --prefer-source` (9 min, 195 git clones), the PHPStan phar fetched from `raw.githubusercontent.com` through the proxy and checksum-verified against `scripts/phpstan.sha256`, Wayfinder modules generated on install, `npm run build` with `fonts.bunny.net` reachable (self-hosted fonts, no `VITE_FONTS_INLINE` needed), and the first authenticated `/ops/status` read from any session (`200`, rehearsal healthy, token never printed).
- The one amber — `composer test` 497 of 2646 red — was the environment variables above, not PostgreSQL 16 (the cycle 16 §6 theory is withdrawn). Control run with the five keys unset: 2646 passed, 13412 assertions, on PostgreSQL 16.
- The setup script's `composer install` does not survive into the session (the cached setup took 337 ms and `vendor/` was absent), so the first `composer install` costs ~9–10 minutes per fresh session. The SessionStart hook's `key:generate` and `migrate` therefore failed silently (no `vendor/`); cycle 17 makes the hook say so instead.
- The harness checks out a `claude/<task>` branch, not `main`; docs-only commits are pushed to `main` from it (R210).

## 4. Known differences from local (accepted for the pilot)
- PostgreSQL **16** in the cloud VM, 18 locally and on rehearsal; Redis 7 both. The full suite passes on 16 (2026-10-17). If a test ever depends on a PG-18 feature, switch the hook to `docker compose up -d postgres` with `postgres:18` (Docker is pre-installed).
- `CLAUDE.local.md` does not exist in the cloud: no ssh to rehearsal, so the R91 server checks cannot run there. Since cycle 15 the authenticated `/ops/status` read (token in the environment) plus the HTTPS smoke is the cloud's verification (R213); deploy is `git push origin <sha>:refs/heads/rehearsal`, which works from the cloud.
- `/clear` is not a cloud command — start a new session instead; the method's "clear at END" means "new session".
- R178 (start Herd services) does not apply; the hook above is its cloud equivalent.
