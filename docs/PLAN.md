R166 **11a — verifier tolerance and diagnostics.** In `DailyVideoProvider::verifyWebhook()`: **(a)** accept `X-Webhook-Timestamp` in seconds or milliseconds — a 13-digit (or ≥ 12-digit) value is divided by 1000 before the tolerance check, and the *original header string* is still what is signed; tests for both forms, and for a millisecond stamp outside tolerance. **(b)** On any failed verification for a provider with credentials, write one `Log::warning('video.webhook.rejected', [...])` with: provider code, the reason (`no_key`, `bad_timestamp`, `stale`, `mismatch`), the timestamp header value and its digit count, the signature header's length, the body length, the list of header *names* received (not values), and — for `mismatch` only — whether the signature would have matched with the base64 secret used as a raw key instead of decoded, and whether it would have matched over the JSON-normalised body (`json_encode(json_decode($payload))`) instead of the raw body. Never the secret, never a body, never a signature value. **(c)** If (b) shows a further difference after the owner's re-run, the fix is limited to `verifyWebhook()` and its tests, ADR-017 gains a dated amendment naming Daily's actual scheme, and the diagnostics line stays (it fires only on rejection).
