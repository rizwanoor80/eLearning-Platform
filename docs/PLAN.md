R34 Slots are never offered past `permit_expires_at`: `SlotCalculator` caps the horizon at the permit expiry (exclusive of the expiry day), tested with a permit expiring in five days against a 14-day window. Booking-time re-validation is CP3's.
R35 Match-request budget tiers stay `low|mid|high` with labels Budget-friendly / Mid-range / Premium as content-block strings (editable in admin, no code change to relabel).
R36 Tutor status lifecycle, completed as one piece (CP1 follow-up, designed with R30 in the ADVISOR entry before the first edit): (a) reinstate-from-suspended → `approved` if permit valid and every required document accepted, else `changes_requested`, audited; (b) post-approval re-vetting: an admin may reject a document on an `approved` tutor or add a required document type, which moves the tutor to `changes_requested` (not bookable) with an email naming what is needed, and the wizard's re-entry path covers it; (c) `review_note` cleared on resubmit; (d) replaced document files deleted from disk after the new row is accepted; (e) permit job `onOneServer` + `withoutOverlapping`; (f) approval-time re-check of permit validity and rate-in-band; (g) a permit edit resets the accepted permit scan to pending. Each with tests; every transition in a `TutorStatusTransitions` table with a test per allowed and per forbidden edge.
