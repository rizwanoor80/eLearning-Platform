## Rulings (owner decisions, numbered, carried across revisions)

R193 **Status endpoint (15a).** `GET /ops/status` returns JSON for operators only: `app` (environment, git sha from `composer.json`/`APP_GIT_SHA` or the deploy's `current` symlink target, PHP and Laravel versions, debug flag), `migrations` (pending count), `horizon` (status, supervisors with process counts, master pid), `queues` (size of `default`, failed-jobs count), `scheduler` (last tick age in seconds, read from the `scheduler:ping` the scheduler writes to cache every minute — add that ping), `ledger` (`ledger:verify` result cached for 5 minutes, never run inline), `video` (active provider code, deliveries in the last 24 h by status, stored events in the last 24 h), `mail` (mailer name, from name and address), `settings` (`allow_immediate_booking`, feature flags). **Authentication:** a bearer token the admin generates in Admin → Settings → Operations ("Status token": generate, rotate, revoke; stored hashed; shown once), plus an optional IP allow-list; the endpoint is rate-limited, logs each call to the audit log with the caller IP, and returns 404 (not 401) without a valid token. No secrets, no row data, no user data in the response. A `php artisan ops:status` prints the same JSON locally. R91 gains, as the preferred form from now on: "`curl -s -H 'Authorization: Bearer …' https://rehearsal.trustutor.com/ops/status`, with the token read from the environment variable `TRUSTUTOR_STATUS_TOKEN` and never echoed" — CC uses it from the cloud, and locally may keep the ssh checklist. ADR-026.
