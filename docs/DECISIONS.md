That reopened the uncapped patterns' cost (Finding 2, Medium, `str_repeat('a.', 1000)` measured ~180ms against a 50ms budget) — met by `hasCandidate()`, a cheap non-backtracking presence check run before each of the three bare-domain patterns, skipping the expensive pattern outright when none of its possible ending tokens occur anywhere in the message (a necessary condition for the full pattern to match, so skipping it can never turn a would-be match into a non-match). Two structural alternatives were tried and reverted first, both self-discovered: a possessive outer group (the advisor's own catch — it swallows the final label and leaves nothing for the mandatory ending, unmasking `mysite.com`), and a lookahead-guarded outer group (breaks `wa.me`-shaped domains whose first label alone looks like a complete ending). **New known limit, disclosed not fixed:** `hasCandidate()` bounds cost only while its gate stays closed; once an ending token is present anywhere in the message, the full pattern still runs, and `-` sits in both the domain LABEL class and the JUNK class, making the outer `(?:label junk)+` group a classic `(a+)+` catastrophic-backtracking shape — `str_repeat('a-', 20).' ok'` (43 characters, an ordinary-looking short hyphenated word before a common two-letter word) already exhausts the default `pcre.backtrack_limit` and throws.
